### Critical Translation Notes

1. **FK columns → Relationships**: In the NHibernate entities, `OrderLine.OrderID` is a scalar int property. In Neo4j, this is the `ORDERS` relationship. The NHibernate code uses `ol.OrderID == orderId` for filtering; Neo4j requires traversing `(ol)-[:ORDERS]->(o:Order)` and matching on `o.orderId`.

2. **BIT → Integer 0/1**: MSSQL `bit` columns map to Neo4j Integer (0/1), not Boolean.

3. **DECIMAL → Float**: MSSQL `decimal` values map to Neo4j `Float`. This is lossy for high-precision financial data.

4. **DateTime → String**: MSSQL `date`/`datetime2` values are stored as ISO-8601 strings in Neo4j. String comparison works for equality but range queries need care.

5. **Collection navigation**: `Order.OrderLines` (NHibernate `Bag`/`OneToMany`) becomes `(o:Order)<-[:ORDERS]-(ol:OrderLine)` in Neo4j.

6. **`IsIdentity` = 0**: All PKs in MSSQL show `IsIdentity=0` in the system query but the NHibernate mapping uses `Generators.Identity` — IDs are pre-assigned in the migrated Neo4j data.

7. **Missing properties on Neo4j Order nodes**: `Comments`, `DeliveryInstructions`, `InternalComments` are defined in the mapping but absent from actual Neo4j nodes (all null in MSSQL sample).

8. **Native SQL queries (Query13, Query14)** use `JSON_VALUE` and `OPENJSON` on `CustomFields` and `OtherLanguages`. In Neo4j these are plain strings containing JSON — Cypher has `apoc.convert.fromJsonMap`/`fromJsonList` for parsing, or `toString()` + string matching.

9. **`CONTAINS` (Query5)**: MSSQL `LIKE '%text%'` via NHibernate `.Contains()` maps to Cypher `ol.description CONTAINS 'C++'`.

10. **The `SupplierContactInfo`, `SupplierBankAccount`, `SupplierAccounts`, `PurchaseOrderInfo` DTOs** are projection types not mapped to any database table — they are query result shapes only.
