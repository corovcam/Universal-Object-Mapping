### Key Relationship/Difference Summary

1. **FK columns become relationships** — `OrderLine.OrderID`, `OrderLine.StockItemID`, `OrderLine.LastEditedBy`, `Order.CustomerID`, `Order.LastEditedBy`, `Order.SalespersonPersonID`, etc., are all replaced by graph relationships. The ID foreign key columns do not exist as properties in Neo4j.

2. **Missing properties in Neo4j Order node**: `comments`, `deliveryInstructions`, `internalComments` exist in SQL Orders table but are **absent** from Neo4j Order nodes.

3. **Missing properties in Neo4j PurchaseOrder node**: `comments`, `internalComments` exist in SQL PurchaseOrders but are absent from Neo4j.

4. **PEOPLE relationship is overloaded** — A single `PEOPLE` relationship type from Order→Person represents all four SQL FK roles (SalespersonPersonID, ContactPersonID, PickedByPersonID, LastEditedBy) with no distinguishing property.

5. **Order.OrderLines on C# class** — The C# `Order` class has `List<OrderLine> OrderLines` but the Neo4j Order node has no such collection property. Instead, traversal from Order via `(OrderLine)-[:ORDERS]->(Order)` (inbound) gets the OrderLines.

6. **CustomerTransaction.CustomerID** — In SQL it's a column; in Neo4j it's the `(CustomerTransaction)-[:CUSTOMERS]->(Customer)` relationship.

7. **PurchaseOrder.SupplierID** — In SQL it's a column; in Neo4j it's `(PurchaseOrder)-[:SUPPLIERS]->(Supplier)`.

8. **C# Supplier split vs Neo4j unified** — The C# code splits Supplier into `Supplier`, `SupplierContactInfo`, `SupplierBankAccount` classes, but Neo4j has all fields in a single `Supplier` node.

9. **JSON fields** — `CustomFields` and `OtherLanguages` are stored as plain JSON strings in Neo4j (not parsed into maps/arrays), so Cypher queries would need string matching or APOC JSON functions rather than property traversal. `CustomFields` is an object `{"Title": "Team Member", ...}` and `OtherLanguages` is an array `["Slovak", ...]`.
